# 是什么

【操作系统】就是一个程序，当前的东西运行完了就把下一个拉进来；辅助用户工作的程序
【进程】（active entity）被加载到内存并运行的程序（passive entity）
终止之后回收可回收的资源
【program counter/PC】：确定一个程序下一个要进行哪条指令
三种系统：
【批处理系统】一个一个加的，但是有点亏，因为io操作可能需要等很久
【多道批处理系统】当前程序io的时候加载另一个job进来跑；但是可能一直不理用户，用户体验不好
【并发/concurrency】一个没完的时候另一个就在跑了，但是可能这跑一会儿那跑一会儿；在进程/线程之间多路复用CPU（Concurrency by multiplexing the CPUs among the processes / threads）
【并行】严格并行，多kernel

| 【multi-programming】 | 同时加载多个程序到同一个内存中运行使用资源角度                   | 关注cpu运行效率 |
| ------------------- | ----------------------------------------- | --------- |
| 【multitasking】      | 多个用户同时在一个电脑中进行，认为在使用一个独立的计算机（分时共享）；用户交互角度 | 关心交互性     |

【分时系统】切分成时间片，一段时间分给一个进程。不是批处理系统，因为批处理是一个弄完再弄另外一个
【kernel】一直在运行的核心program
【system program】一些辅助kernel但是不是自己安上去的东西
![[图源/图源2/Pasted image 20260824174455.png]]
操作系统是连接用户程序和硬件的中间部分：为上面的程序提供一些接口
处理外部输入：用户接口连接GUI图形化界面（鼠标/touch screen），CLI（键盘这种）和文件系统交互
然后系统调用～system calls：调用操作系统的service
包括：

- 程序执行，io，文件系统，电脑间通信，分配资源，账户权限，安全部分，错误探测/中断处理

## 功能

交流、错误检测、用户接口、执行程序、io操作、文件系统操作

## 中断处理

【中断驱动】收回控制权
【interrupt request line】执行每条指令之后检测一次这条硬件线路
～类似于计算机组成的exception，发生exception之后查中断向量表然后跳转到对应处理程序

- 多级中断：就是一个中断被不断打断了，生成新的子中断进程
- 在一条中断正在保存现场的时候不支持接受另外的中断
  【nonmaskable interrupt】为不可恢复的内存错误事件保留，优先级比较高，需要在条件允许的时候第一时间响应
  【maskable interrupt】可以被cpu关闭
  【timer】在操作系统将cpu的控制权交给一个程序前开一个，回到0的时候产生一个中断还给操作系统，来保持控制权/分时系统
  【硬中断】io导致的中断
  【软中断/trap】软件错误/用户systemcall

### interrupt的处理流程

1. 存储当前CPU状态和指令
2. 判断中断类型
3. 跳转到对应的中断处理程序

### 两种io method

同步io：执行完io之后将控制权返回给用户
异步io：执行io的时候立刻将控制权返回给用户
\- 交互性比较好，可以并发地做很多的事情
\- 并行，希望记住不同发出的io请求：通过device-status table

## Dual-mode\&multimode

- 双模式/多模式提供硬件隔离，保证一个错误的程序不会造成其它程序的错误运行/无限循环/软件错误导致的异常或者trap，最多自己崩溃一下
  - 内核发现是非法访问会杀掉该进程
- 【mode bit】分成两种区域：系统模式和用户模式，用户模式下会把所有特权指令视为无效指令，kernel mode下才能进行&实现interrupt
- 用户想要执行特权指令可以通过system call向系统提交请求
  - ecall：系统调用的一条指令
- 【trap】从用户态进入kernel态（软中断）
- 多mode：【privilege level】支持多于user mode但是少于kernel mode的指令
  ==如果在用户态试图使用privilege指令会进入内核态，因为算错误指令需要exception，但是并不会执行那个指令本身==

### system call

通常通过高层级API而不是直接的系统调用来使用；为了调用系统资源
参数传递：寄存器直接传递/放在内存中用寄存器传递地址/栈传递
例子：进程控制/文件/设备；信息获取/交流/文件保护权限

## 内存分配

优化cpu利用率&反应的时候memory里面有什么

1. 重分配
2. 每个进程怎么分配内存
3. 一片有限的内存里面哪些进程可以进来
4. 【spooling】一个作业的输出，与另一个作业的输入，在时间上重叠进行
   作业A计算完毕，它的**输出**被快速写入磁盘上的一个“输出井（Output Spool）”中。CPU立刻转向去处理下一个作业B（这就是**重叠**）

# 文件系统管理

控制访问权限
将存储单元抽象为file，本质为字节流，进入file system管理

【policy】确定具体做了什么事
【mechanism】定义做事的方式
==重要的事：策略和机制相分离==

一个好的操作系统应该是分层的，上层调用下层，上层的功能依赖于下层的功能，往往上层功能更综合，最内层是hardware

【monolithic structure】单一的巨大的内核，开发的时候做的比较简单&做的人强强
【microkernel】只保留一些最基本的功能，其他功能移交给user mode实现
