【裸机】未安装任何（包括操作系统在内）软件的计算机
【四大资源】处理器、存储器、设备、文件
【基本特征】并发、共享（最基本的两个特征，互为前提）、虚拟、异步
【共享】
\- 互斥共享
【临界资源】一段时间内只允许一个进程访问的资源
\- 同时访问
【脱机I/O】完全由外围机独立完成，脱离主机直接控制
【联机I/O】由主机直接管理I/O设备

# 是什么

【操作系统】就是一个程序，当前的东西运行完了就把下一个拉进来；辅助用户工作的程序；
【扩充机器】经过操作系统，将裸机抽象并扩展成一台功能更强&使用更便捷的逻辑机器
【功能】交流、用户接口、执行程序、io操作、文件系统操作、分配资源，账户权限，安全部分，错误探测/中断处理
【进程】（active entity）被加载到内存并运行的程序（passive entity）
终止之后回收可回收的资源
【program counter/PC】：确定一个程序下一个要进行哪条指令
三种系统：
【批处理系统】一个一个加的，但是有点亏，因为io操作可能需要等很久
单道批处理系统有一个==监督程序==来控制作业自动运行
【多道批处理系统】当前程序io的时候加载另一个job进来跑；但是可能一直不理用户，用户体验不好
【并发/concurrency】一个没完的时候另一个就在跑了，但是可能这跑一会儿那跑一会儿；在进程/线程之间多路复用CPU（Concurrency by multiplexing the CPUs among the processes / threads）
【并行】严格并行，多kernel
在==管理程序==的控制下并发执行，共享系统资源，依赖中断技术（因为要在一个程序因I/O请求而暂停运行的时候立即切换到另一个就绪程序之中）
\- 好吧竞争所以相互制约 感觉也能说通🤔

| 【multi-programming】 | 同时加载多个程序到同一个内存中运行使用资源角度                   | 关注cpu运行效率 |
| ------------------- | ----------------------------------------- | --------- |
| 【multitasking】      | 多个用户同时在一个电脑中进行，认为在使用一个独立的计算机（分时共享）；用户交互角度 | 关心交互性     |

【分时系统】切分成时间片，一段时间分给一个进程。不是批处理系统，因为批处理是一个弄完再弄另外一个
【实时操作系统】在严格的时间限制内完成关键任务而设计的系统，确保高优先级任务能够及时地获得处理器资源
包含硬（任务必须在规定的截止时间前完成）和软（允许偶尔错过截止时间只要不造成永久性损害）
【网络操作系统】显式指定远程资源的位置
【kernel】一直在运行的核心program
【system program】一些辅助kernel但是不是自己安上去的东西

# 中断处理

【中断驱动】收回控制权
【interrupt request line】执行每条指令之后检测一次这条硬件线路
～类似于计算机组成的exception，发生exception之后查中断向量表然后跳转到对应处理程序

- 多级中断：就是一个中断被不断打断了，生成新的子中断进程
- 在一条中断正在保存现场的时候不支持接受另外的中断
  【nonmaskable interrupt】为不可恢复的内存错误事件保留，优先级比较高，需要在条件允许的时候第一时间响应，这里指外中断，但是内中断（异常）也是不可屏蔽的
  【maskable interrupt】可以被cpu关闭，通过改变屏蔽字可以实现多重中断
  【timer】在操作系统将cpu的控制权交给一个程序前开一个，回到0的时候产生一个中断还给操作系统，来保持控制权/分时系统
  【硬中断】io导致的中断
  【软中断/trap】软件错误/用户systemcall

## interrupt的处理流程

1. 存储当前CPU状态和指令
2. 判断中断类型
3. 跳转到对应的中断处理程序，异常重返第i条指令，中断重返第i+1条指令

# 两种io method

同步io：执行完io之后将控制权返回给用户
异步io：执行io的时候立刻将控制权返回给用户
\- 交互性比较好，可以并发地做很多的事情
\- 并行，希望记住不同发出的io请求：通过device-status table

# isolation

## Dual-mode\&multimode

- 双模式/多模式提供硬件隔离，保证一个错误的程序不会造成其它程序的错误运行/无限循环/软件错误导致的异常或者trap，最多自己崩溃一下
  - 内核发现是非法访问会杀掉该进程
- 【mode bit】分成两种区域：系统模式和用户模式，用户模式下会把所有特权指令视为无效指令，kernel mode下才能进行&实现interrupt
- 用户想要执行特权指令可以通过system call向系统提交请求
  - ecall：系统调用的一条指令
- ==操作系统获得控制权的时候必处于内核态==
- 多mode：【privilege level】支持多于user mode但是少于kernel mode的指令
  ==如果在用户态试图使用privilege指令会进入内核态，因为算错误指令需要exception，但是并不会执行那个指令本身==

# 结构

分层：运行效率较低：执行一个高层功能需要穿越多个中间层
一个好的操作系统应该是分层的，上层调用下层，上层的功能依赖于下层的功能，往往上层功能更综合，最内层是hardware
衡量模块独立性的标准：
【内聚性】模块内部各组成部分间联系的紧密程度
【耦合度】模块间相互依赖和影响的程度

【宏内核】模块集成在一个紧密耦合的整体中，单一的巨大的内核，开发的时候做的比较简单&做的人强强
【微内核】保留最基本的功能在内核中，将文件系统、设备驱动等服务移至用户态运行，之间有一个【消息传递机制】
分成微内核和多个服务器
某一模块发生故障时，仅该模块崩溃，系统可重起该模块；宏内核中如果文件系统（运行于内核态）崩溃将直接引发系统崩溃
\- 采用面向对象技术

- 采用“机制与策略分离”的设计原则，常见功能有：

1. 进程管理
2. 低级存储器管理
3. 中断和陷入处理
   【机制/mechanism】实现功能的具体执行机构
   【策略/policy】在机制基础上通过参数/算法实现优化/差异化目标，确定具体做了什么事
   【混合内核】现代系统采用：保留部分微内核思想；将一些高频但不是必须的指令/服务同样移入内核来提升性能；但同时会使微内核的容量明显增大
   【外核】将物理资源直接暴露给用户程序，自身仅负责资源的安全分配与隔离
   在外核之上的用户空间直接构建：：系统性能&灵活性较好
   【库操作系统】直接操作物理资源，无需经过传统内核的强制性抽象层，自主实现操作系统功能如 文件系统、进程调度、虚拟内存管理etc

# 操作系统建立步骤引导

1. CPU从ROM读取并执行BIOS基本输入/输出系统程序。BIOS初始化基本硬件，建立中断向量表（存储各个中断入口的地址），为引导阶段的设备访问提供支持（启动具体的设备）
2. BIOS执行通电自检POST，检测CPU、内存及外设是否正常，根据CMOS设置确定启动设备优先级并选择首个有效的启动设备（硬盘、U盘）
   【CMOS】一个主板上由电池供电的配置存储器，保存启动的设备优先级
3. 将所选启动设备的首扇区（MBR主引导记录，包括引导代码与硬盘分区表）加载到内存中
4. MBR定位活动分区并加载分区引导记录（PBR）
5. PBR加载硬盘中的启动管理器，提供多操作系统/内核版本的选择界面，用于引导操作系统
6. 加载OS kernel
7. 内核初始化与用户环境启动：初始化完成后内核启动首个用户态进程，由此逐步构建完整的用户操作环境
