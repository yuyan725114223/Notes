## 机器语言\&MASM

机器语言：1-15B
有些位是确定的，剩下的位是指令的不同变种确定的
操作模式：64位下标准的地址是64位，但是标准的操作数是==32==位的
处理器指令：伪代码，告诉是哪个指令集/处理器类型/标准的操作数or地址位数/允许的语法
MASM不同的处理器指令

- 16-bit：8086，1-286
- 32：3-686
- FP：8087，2-387
- 特殊目的：MMX，XMM
  这样可以：
- 确定指令有效性（是否能和寄存器位数对上）
- 产生正确的指令/地址位数

# 64位

加了一个第一个字节，后面的字节设计还是和32位相同的
32已经不够找16个寄存器了，所以要扩展一下，、【REX（register extension）】使能：操作符大小扩展，支持一下16位寻址
本来只能访问8个寄存器，加了之后可以访问寄存器r8-15
默认是0100WRXB
W：操作数大小，0表示默认32位，1表示64位操作数
R：modRM中reg的扩展位
X：SIB index字段的扩展位
B：扩展到16个reg，补一下后面可能出现的mem寻址；如果是100就扩展扩展里面的base；也可以作为opcode？

- 放在legacy前缀之后，操作码之前

# 前缀

分4组，一条指令只能有一个前缀，前后顺序可换

1. 锁定内存访问（只有特定的指令能够使用）/重复
   1. 位操作
   2. 逻辑计算
   3. 交换
      写内存并且是这三类的时候能够加锁
2. 段重载：XS段重写（其中X为变量字符）
   处理器会自动选择一个标准段。如果加了段重载前缀就可以更换一个默认段
   编码/链接加到目标代码，必有影响
3. 操作数大小重载
4. 内存地址大小重载（上面的66和67）
   _1byte不会变成32bit，这个时候直接改了opcode，所以没有加oprand prefix_

## vex前缀

向量扩展指令：C5/C4前缀，后面接了2个/3个字节
XMM/YMM不够放；操作数不用放，但是向量运算经常需要非破坏性三操作数
操作数不够怎么办：加一个字节/两个字节的逃逸码（escape sequence）就说明可能是新的指令，进入二级指令表

# 数据移动指令

load effective address：
LEA：加载近指针（做表达式计算的结果）
seg和offset返回内存位置的段和偏移值，mov di, offset data2的效果是和lea si, data1的效果一样的

> offset和lea都能做偏移地址，有什么差异？
> offset的效率更高，因为lea需要在实时运行状态。offset在汇编的时候就取了
> mov也很efficient
> 如果源寄存器不是直接的偏移而是表达式的时候需要使用lea，可以多合一直接计算/存储

LDS,ES,FS,GS,SS：加载远指令 当前的段和offset
段长度都是16位的
加载段地址/段选择子，加载到DS/ES；偏移地址存储到寄存器
==内存中地址模式：偏移在前，段地址在后（低字节在前）==
==段寄存器不能直接装内存数据==。所以需要先通过一个中间寄存器AX
CLI：关闭中断：防止下面的任务被打断
STI：开中断

## 指令数据传输

都是隐含操作数

# 汇编器细节

【directives】指示汇编器做一些工作：生成机器码/分配内存；只会影响编译器不影响最终的代码生成
【instruction】直接面向CPU规划，最终生成可执行的机器码

## MASM里的directive

指示编译器如何处理程序段的操作数
示例：
![[图源/图源2/Pasted image 20261111104636.png]]
db：这种还给对应位置的内存标记了一个symbolic name
【DUP】一次性初始化好几个，下面两条指令等价

```masm
DATA1 DB 0, 0, 0, 0, 0
DATA2 DB 5 DUP(0) ； reserves 5 bytes of 0
```

- 内存预定空间：dup（）中使用？占位，不初始化成一个具体的值
  【ALIGN】把之后存储的数据放在参数倍数的地址位置上，一般用来双/四字节
  _注意一下mov到寄存器的位数大小_
  【EQU】把一个label设为1/2/4B的数字/ASC2/标签
  【THIS】跟在equ后面 把这个地址设置成一个1/2/4B的标签
  【ORG】改变数据/代码段的起始地址
  【ASSUME】告诉编译器C/D/E/SS对应选择的名字（label）叫什么；应该放在所有最前面，因为每个都要用到
  【segment】定义一个段
  【macro-endm】一个有名字的一块汇编语言陈述（代码/数据）内联扩展

### 【Memory organization】

定义内存相关的属性

#### 全段式定义

```
全都自己写，细节比较多；对所有的assemblers统一
使用.MODEL来判断代码/数据大小
使用segment/assume-ends
```

处理器隐含定义了默认的操作模式
段属性明确定义，可以覆盖默认的，也可编程混合
【END label】告诉链接器程序从该label开始执行

- 对MASM来说是唯一的

- 保护模式：flat
- 段标记：@DATA, @STACK, @CODE
  一般来说会选取能够满足内存需求的最小模型，因为近指针比远指针作用快
