# 32位

## 第一个字节

L位\&D/B位来控制指令模式

- 00:16
- 01:32
- 1-:64
  ![[图源/图源2/Pasted image 20261013133640.png]]
  只有opcode是必选的，其它都是可选的
  猜测在讲指令格式
  opcode前6位是真正的opcode，后两位是D和W

D：direction：表示数据从寄存器-内存or内存-寄存器
寻址方式/两个操作数的编码-哪个寄存器
（）以register为中心，因为只有一种没有reg

> 为什么需要一个方向位？
> x86绝大部分指令都有一个是内存访问的指令
> 一般来说只有一个内存
> 把访问内存应该会有的多出来的2个放到前面，然后再通过一个D来控制which是mem

W：0:单字节byte；1:当前的default size
具体是什么size取决于当前的运行模式
通过前缀来弥补32位增加一种双字节的方式？66H operand prefix和67H address prefix

## 第二个字节

寄存器编码顺序是ACDB
可能会有一个重操作码放在后面
==重点==
除了11情况下都有内存寻址

## 第三个字节

扩展出来的scaled index
前两个字符表示\*1/2/4/8，后3，3个分别代表index，base
ESP不能做index只能做base

# 64位

加了一个第一个字节，后面的字节设计还是和32位相同的
32已经不够找16个寄存器了，所以要扩展一下，加前缀REX（register extension）支持一下16位寻址
一个字节：前4位寄存器地址？
后四位分别是：

- W：和上面的一样
- R：扩展到16个reg，补一下后面可能出现的寄存器寻址
- X：扩展扩展中的index
- B：扩展到16个reg，补一下后面可能出现的mem寻址；如果是100就扩展扩展里面的base；也可以作为opcode？

# 前缀

分4组，一组里面只能是一个，前后顺序可换

1. 锁定内存访问
   1. 位操作
   2. 逻辑计算
   3. 交换
      写内存并且是这三类
2. 段重载
   编码/链接加到目标代码，必有影响
3. 操作数重载
4. 内存重载

操作码很难区分是哪条mov指令
靠前缀控制操作数的长度
66:在16和32位之间切换：16位加了变成32，32加了变成16
67:也是加了翻转
相同的机器码不知道运行模式也很难进行反汇编
一道神奇的题目，1byte不会变成32bit，这个时候直接改了opcode，所以没有加oprand prefix

向量扩展指令：C5/C4前缀，后面接了2个/3个字节

操作数不够怎么办：加一个逃逸码：escape sequence：如果加了一个就说明可能是新的指令

# 指令

load effective address：LEA：加载近指针（做表达式计算的结果）
都能做偏移地址，有什么差异？
offset的效率更高，因为lea需要在实时运行状态。offset在汇编的时候就取了
如果不是直接的偏移而是表达式的时候需要使用lea
LDS,ES,FS,GS,SS：当前的段和offset
段长度都是16位的
CLI：关闭中断：防止下面的任务被打断
STI：开中断
SP不能直接和内存交互，所以需要先通过一个中间寄存器
LSP x x：一键恢复了

## 指令数据传输

都是隐含操作数
LODS：从指定的SI寄存器中直接取字符串到寄存器里面，加个后缀看看取多少
direction决定取完之后SI往哪个方向移动
这里不会使用rep，因为寄存器的移动没有什么作用，相邻的寄存器没有位置相关（？）
STOS：可以加rep，对一片内存进行初始化

REP前缀
