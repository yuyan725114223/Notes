# jump

结果会放到flag bit，然后被conditional jump指令检测
loop也算jump

## 无条件跳转

- 短跳（2）：当前+相对offset
  - 跳转到+127/-128字节的位置（注意这里刚好一共是2^8
  - 也叫相对跳转，因为存的是相对的位移而不是直接的地址，而且注意是下一条指令的位置再加位移
    程序放进内存的时候位置是不固定的，写得时候芝士一个硬盘上的exe文件，要加载到内存里面才能执行（因为也不能在硬盘里面运行程序吧！太慢了
  - 但是内存里面哪里有空的不是很确定
  - 所以需要使用相对跳转来定位一个完整的程序，程序内跳转的相对位置要不变！不然会跳到乱七八糟的地方去：【重定位】
  - 【CS】代码段寄存器的起始地址
  - 【CS:IP】逻辑地址：cs\*16+IP
  - 使用跳转方法的时候注意标签后面需要加一个冒号；只有跳转/调用指令引用标签的时候汇编能够使用冒号
- 近跳（3）：跳到当前代码段位置+-32k字节（当然这是实模式下的，不同模式下的状况不是很一样
  - 默认的跳转方式
  - 可重定位（没有加特殊标签
  - 实模式段内随便跳
  - 区别不是特别大除了距离远了一点之外；注意这里存放是小的在比较大的地址
  - 指令最后加一个R：可重定位的标志：告诉连接器该字段地址需要按照最终装入位置重新计算
  - 寄存器跳转/非直接下标跳转
  - 也可以使用【】来进行双重跳转
- 远跳（5）：真实内存系统里面跳转到任意内存位置
  - 前两个字节存储偏移地址，后两个存储新的段地址
  - 保护模式：内存访问需要经过操作系统的登记检查->段寄存器内存储段选择子（类似数组下标）指向GDT全局描述符表活LDT局部描述符表里的某一项
    - 实模式的IDT也叫IVT
    - descriptor：8个字节：基址（在内存中的真实起始地址），界限（到底有多长？！），访问权限
    - 这样操作系统就获得了控制权：权限检查！内存保护（如果超过描述符里面的limit就直接报错！不会乱写），多任务隔离！
  - 哦这里就接到一个描述符还有一个16/32位的偏移地址
  - 使用FAR PTR指针（如果在本文件内）
  - EXTERN 标号：FAR（如果在外部文件里）
  - far label：也可以使用两个冒号
  - table data默认Define doubleword，因为有CS：IP4个字节
    其中上面两个叫做分段内跳转，远眺叫做分段间跳转
    ![[图源/图源2/Pasted image 20261103210949.png]]

## 条件跳转

- 检查flag bit，比如sign, zero, carry, parity, overflow
- 一般来说只会test一个flag bit，但是有些也会两个
- jcc跳不到很远的地方，因为只允许相对offset
  ![[图源/图源2/Pasted image 20261103224023.png]]
  通过操作一下：先反转了bit，如果是0就跳到下面的skip位置，也就是原路向下运行，但是如果是1就直接运行下一条无条件跳转cmp，直接跳到了远的地方，相当于如果满足条件就跳到远的地方
- 比较无符号数的时候使用JA, JB, JAE, JBE（above和below）
- 比较有符号数的时候使用JG, JL, JGE, JLE（greater和less）
- 也有些不test flag而是test cx和ecx：JEXZ：如果EX是0就跳转，否则不跳转

## conditional set

检查EFLAGS里面的寄存器内容，如果满足条件就设置相应位置的内存/寄存器的值为1，不满足条件就设为0
【EFLAGS】状态位（上一步运算的结果）+控制位+系统操作位（只有操作系统允许访问这些，单步调试、特权级、虚拟模式等）

- 可以用相应寄存器内的01标志来确定对应flags到底是否满足
- 可以用来保存当前的状态，如果该状态在非常久之后才会用到的话
  【目的】
- 将控制流转化为data
- 打包原子化了一个判断指令，避免了命令跳转导致的流水线阻塞
- 可以直接实现布尔逻辑，比如可以将表达式的结果赋值给另外一个变量

# procedure

一组执行一个task的指令；存储在内存里面的一个可复用的软件段部分；函数、子路程、方法
PROC开始，ENDP结束

- 分为NEAR/FAR
- 可以被所有的程序使用的procedures叫远进程，只有一些可以的叫近进程
  RET可以用于从一个procedure中退出
  USES：使用一定数量的寄存器存进栈里然后pop出来；声明该procedure里要使用到的寄存器

## calls

和跳转指令的区别：在访问跳转之前存储一下调用指令之后的地址

- 近跳（3）：段内：CS寄存器不动，因为段没有改变
  - 需要程序返回的时候自己处理压进栈里面的参数：比如可以栈指针直接+n跳掉
- 远跳（5）：不同段；跳之前会把原来的CS和IP都存到栈上；取回一个8B地址（这里就是绝对地址了）
  - DOS二号功能：要显示的字符放在DL上（D的低位地址）
- inter-privilege-level far call：同一个段但是不同的特权等级代码之间的跳转
  - 如果需要权限传递，processor会先检查一下
  1. 定义一个conforming code segment，给不同特权阶级共享libraries
  2. 【gates】：一种特殊的段描述符
  3. 使用快速系统调用指令：(SYSCALL/SYSRET or SYSENTER /SYSEXIT)
- task switch：不同任务之间的跳转
  后两个只能在保护模式里面执行
  寄存器如果是DW也可能被直接识别为远跳

arm是存在寄存器里面的，避免内存访问泄漏；不过如果有一个及以上的调用发生的时候还是得直接存在栈里面

### 特权阶级

【CPL】当前运行者的特权阶级
【RPL】段选择子的特权阶级，请求者声称的身份
【DPL】目标段的特权阶级
只有在DPL比CPL和RPL中更大的那个更大的时候会访问对应的目标段，否则报异常13；需要先比最大的为了防止跑到内核代码之后声称自己就是高特权级的

#### conforming-segment符合段

如果描述符里面有conforming bit，这个可执行的段就叫conforming-segment

- 如果bit开了的话可以访问特权级比自己高的段
- 允许不同特权级的procedure共享
- 如果有的话就不检查RPL了
- 如果控制权传到这种段的话CPL不会改变
- 这里特权阶级访问的方向会反转，高特权级反而无法访问该字段

#### 门描述符

有指针指向代码段的描述符；用于保护模式下的控制流动
四种：

- call：不同特权阶级之间的代码接口
- trap\&interrupt：访问的代码是trap或者interrupt
- task：切换任务
  在GDT/LDT里面，用来访问不同任务
  call开不开conforming都可以使用比门更高特权级的代码，jmp如果不开conforming只能访问和门同一个特权级的代码；不管怎么说更低的肯定不行

# interrupts

处理异常/中断的系统软件服务保存被打断的程序的状态
【IVT/中断向量表】实模式，在内存最开头：处理程序在哪（保护模式认为容易被劫持）
【IDT/中断描述符表】保护模式/长模式，位置可变，由IDTR寄存器指定：入口地址+特权级+类型
software interrupts using the INT n instruction are synchronous.一条一条指令执行当然是同步的了
I flag bit用STI/CLI控制变成0/1
（首先关中断，在最开始的一系列设置设置完之后）必须尽早开中断，PC IO驱动，如果等了太久可能会缓冲区溢出，导致大问题

## 分类

- 可屏蔽中断：走INTR，如果中断IF=0的时候就先记着不处理，只有IF=1的时候才处理
- 不可屏蔽中断：非常优先，必须先处理，不受IF值的影响

## 指令

- INT N：注意实模式下还要\*4；保护模式\*8
  - 可以替代CALL来访问系统procedure，并且指令比较短，因为实际的地址存储在一个表里面
- INT1
- INT3：1B，作为GDB里面打断点使用
  - 如果超过一个B的话会出现问题：跳转的时候可能会跳到INT3中间的部分
  - 把断点位置的操作码记住，然后偷偷换掉，程序走到这里的时候就会坏掉然后跳转到中断处理器trap的位置把当前的各个信息都报出来
  - 非侵入性软件中断
- INTO：处理溢出情形

# exceptions

一般来说会有一个助记符包括：# 两个字母（opcode），比如#GP(0)

- 程序错误：程序进行过程中产生的异常（被动）
- 软件产生：主动请求异常机制干某件事情
- 机器检验：CPU芯片硬件出错的时候触发的自我检测（触发mc异常，通知操作系统：硬件出问题，快记录/停机）
  非精确异常：not restartable，因为前后不是同步的
  中断向量里面前32个给CPU自己定义的异常/中断使用（自检触发的固定事件）；32-255给操作系统&硬件设备自由分配
- 实模式存在内存最开始的1024B里
- Clears FLAGS.IF to 0：清中断

不完全是多级中断，因为有些多次中断不是double-fault exception
：意思是第二个异常把CPU处理异常的基础设备破坏了

如果进入double-fault处理机制的过程中又出现了问题，处理器就会直接进入【shutdown mode】

## 三类

- faults：报告在事发之前：在错误的指令还没成功执行完的时候CPU就喊停了，处理完exception之后还要重新回来处理该条指令
- traps：已经执行完的指令发现出现中断，下一个执行
  这两个都是精确异常
- aborts：非精确异常并且不允许可靠的重开始

# machine control instructions

： 处理carry bit，停止指令，展开其他指令
STC，CLC，CMC
HLT：如果中断/调试异常/硬件重置
NOP：啥都不干；可以使用不同长度的NOP来完成指令对齐（2-9）（灵活应用前缀）

## lock prefix

RMW：读完改一下然后写回去
单处理器：因为只有1条所以是exclusive访问内存的
多：lost update：可能会有的更改没有生效（数据竞争）
可以给想要原子化的操作指令加一个LOCK前缀，这样别的就改不了该内存了
方式：通过cache一致性协议锁掉cache line
生效指令：
– ADC, ADD, AND, DEC, INC, NEG, NOT, OR, SBB, SUB, XOR
– CMPXCHG, CMPXCHG8B, CMPXCHG16B, XADD and XCHG
– BTC, BTR, BTS

确保第一个操作数载第二个操作数（内存 有两个数构成范围限制）的范围之内
