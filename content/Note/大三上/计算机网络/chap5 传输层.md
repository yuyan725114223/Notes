# 功能

- 端到端的通信：SAP
- 提供有连接和无连接的两种通信方式
- 网络层是isp提供的服务，但是传输层可以自己选择协议来提高网络的服务质量
- 包装成传输层的语言，传输服务器给用户提供一组接口；网络服务类似于汇编语言，传输服务类似于高级语言
  【SAP】指定传输进程。16bit
  【segment】传输层的传输单位
  ![[图源/图源2/Pasted image 20260819115755.png]]

# UCP：无连接

不可靠：适合一次性传输数据较少/不那么注重可靠但是不能容忍延迟的应用
多路复用：用端口做
进行一些总体的checksum，毕竟前面什么检查都没做

- 如果数据部分长度不是16bit的倍数就末尾补0，但是补的0不会被发出去
- 有UDP header和伪首部

# TCP：有连接

希望可靠传输：一对一面向连接，提供双全工通信，传输可靠、有序、无丢失、不重复
将应用程序传来的结构视为无结构字节流，由协议动态决定![[图源/图源2/Pasted image 20260819140406.png]]【MSS】数据部分的长度
【怎么连接？】必有一方在listen
三次握手和四次挥手
![[图源/图源2/Pasted image 20260819145123.png]]
【two army problem】理论上来说无法保证传到![[图源/图源2/Pasted image 20260819151116.png]]【可靠传输机制】校验机制，序号确认

- 使用超时重传or冗余ack快速重传
  【流量控制】窗口探测避免互相都等的思索
- 不需要一收到要传的数据就马上传递，也可以缓存起来等一下
- 窗口探测计时器使用persistence timer
  【拥塞控制】发送方的窗口考虑
- 接收方缓冲区剩余大小 rwnd
- 网络的拥塞情况 cwnd
- 取这两者的较小值
- 慢开始和拥塞避免：初始cwnd为1，开始指数增加，到达阈值之后每次+1，网络拥塞之后返回到1，同时将阈值设定为网络拥塞的值/2
  【快重传和快恢复】在网络拥堵之后不是变成1而是变成原来堵塞阈值的1/2，如果收到了三个连续的ack就开始快速重传
