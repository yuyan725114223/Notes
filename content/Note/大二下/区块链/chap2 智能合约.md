# 实验2

- 多节点geth部署，共享一条私有链+truffle（专业框架）/ganache（区块链模拟器）智能合约自动化开发、部署和测试
- 同一个区块链网络里的节点应该拥有一样的创始块规则
- **开发者写Solidity代码（MathContract.sol）** → **Truffle编译成字节码** → **通过配置文件连接Ganache（本地模拟器）** → **一键部署** → **执行JS测试脚本断言运算结果**

```bash
geth --port 8100 \                      # ① P2P通讯端口（两节点不能重复）
     --networkid 666 \                  # ② 网络标识，必须等于chainId
     --datadir ./multiNodes \
     --maxpeers=3 \                     # ③ 最大连接数（实验设小一点）
     --http --http.port 8545 \          # ④ HTTP-RPC端口（两节点不能重复）
     --http.addr 虚拟机IP \              # ⑤ 监听指定IP（让另一台能访问）
     --http.corsdomain "*" \            # ⑥ 允许跨域（MetaMask等工具访问）
     --http.api="eth,web3,personal,admin,txpool" \ # ⑦ 开放完整管理权限
     console \
     --allow-insecure-unlock \
     --nodiscover                        # ⑧ 最关键的新参数！
```

最后一个参数的意思是不要自动广播自己，仅接受手动添加；要更改到不同的p2p端口和http端口
添加静态对等节点（Static Peer）：**`admin.addPeer("对方enode")`**：你在节点A的控制台，贴上节点B的enode

```text
enode://[64位十六进制公钥]@[IP]:[端口]?discport=0
```

之后三次握手建立连接，如果peers出现了对端节点的信息，说明成功添加了好友
p2p连接之后A挖出的区块广播给节点B，B经过严格的校验之后通过追加到自己的本地链上；如果建立连接成功两边的blocknumber应该是一样的
