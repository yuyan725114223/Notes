# 是什么
【操作系统】就是一个程序，当前的东西运行完了就把下一个拉进来；辅助用户工作的程序
【进程】被加载到内存并运行的程序
三种系统：
【批处理系统】一个一个加的，但是有点亏，因为io操作可能需要等很久
【多道批处理系统】当前程序io的时候加载另一个job进来跑；但是可能一直不理用户，用户体验不好
	【并发】一个没完的时候另一个就在跑了，但是可能这跑一会儿那跑一会儿
	【并行】严格并行，多kernel
【分时系统】切分成时间片，一段时间分给一个进程。不是批处理系统，因为批处理是一个弄完再弄另外一个
【kernel】一直在运行的核心program
【system program】一些辅助kernel但是不是自己安上去的东西

操作系统是连接用户程序和硬件的中间部分：为上面的程序提供一些接口
处理外部输入：用户接口连接GUI图形化界面（鼠标/touch screen），CLI（键盘这种）和文件系统交互
然后系统调用～system calls：调用操作系统的service
包括：
 - 程序执行，io，文件系统，电脑间通信，分配资源，账户权限，安全部分，错误探测/中断处理
# 中断
【中断驱动】收回控制权
【interrupt request line】执行每条指令之后检测一次这条硬件线路
～类似于计算机组成的exception，发生exception之后查中断向量表然后跳转到对应处理程序
- 多级中断：就是一个中断被不断打断了，生成新的子中断进程
- 在一条中断正在保存现场的时候不支持接受另外的中断
【nonmaskable interrupt】为不可恢复的内存错误事件保留，优先级比较高，需要在条件允许的时候第一时间响应
【maskable interrupt】可以被cpu关闭
【timer】在操作系统将cpu的控制权交给一个程序前开一个，回到0的时候产生一个中断还给操作系统，来保持控制权/分时系统
# Dual-mode&multimode
- 双模式/多模式提供硬件隔离，保证一个错误的程序不会造成其它程序的错误运行，最多自己崩溃一下
	- 内核发现是非法访问会杀掉该进程
- 【mode bit】分成两种区域：系统模式和用户模式，用户模式下会把所有特权指令视为无效指令，kernel mode下才能进行&实现interrupt
- 用户想要执行特权指令可以通过system call向系统提交请求
- 【trap】从用户态进入kernel态
- 多mode：【privilege level】支持多于user mode但是少于kernel mode的指令
==如果在用户态试图使用privilege指令会进入内核态，因为算错误指令需要exception，但是并不会执行那个指令本身==
