# 广播信道传输协议
【多路访问信道】【随机访问信道】一个意思
【MAC】【介质访问控制子层】确定一下多路访问信道的下一个使用者
	- framing, physical addressing(物理寻址), error control, access control
【LLC】【逻辑链路控制子层】
	- 流量控制
【ALOHA】想发就发 but可能有冲突
	- 冲突的话等待一段随机时间然后重发 以免固定时间之后另一次冲突
	- 最好情况下是1/2e成功概率
【SLOT】分片，只能在每一片开始的时候发，每帧时间<一个slot
【CSMA 1-persistent】发之前先听一下有没有人在发
	因为可能是忙的所以发之前要先监听一下
	但是可能在一半的时候冲突，就是发到一半的时候两边冲了
【p-persistent】听到之后有p的概率发送消息
【nonpersistent】等待一段随机时间之后才发
【collision detection】如果监测到冲突就立即停止传播，然后等待之间之后发送
- 主动检测
==注意2t时间内只能发出一个帧==，$\frac{F}{BW}\ge2t$
## 无冲突协议
【基本位圈协议】每次问一下有谁要发，然后达成一致。之后按协议的顺序逐个发，完成之后进入下一轮协议
【令牌环协议】顺序后移，只有持有token的人能够发消息
【二进制倒计数协议】数四个数，该位是1的先吭声。其实就是大的先发
## 有限竞争协议
自适应树遍历协议：有限次数之内一定能发出去（到叶子节点）

# 网桥
直接连有点问题啊：
- 少部分需要跨局域网交流，这样加大了负载压力
- 物理地址相聚较远的连起来难度比较大
- 如果本来lan运行速度不同，直接连也不能正常工作
so LAN之间还是相互隔离，但是通过网桥互相之间发一下。网桥存储局域网之间的消息，然后分别转发
【混杂模式】局域网内的直接丢掉自己解决，局域网外的帧通过对应端口转发
	应该知道那几个端口在同一边
	&知道发送帧的端口应该在对应的端口，然后逐个添加。这个叫【反向学习】
【直通式交换/虫孔路由】因为地址在一个帧的最前面，一看到地址就开始思考怎么转发，效率比较高
如果全都是点对点的甚至都不会冲突 网桥的好处
【冗余链路】一般会在网桥之间放多几个线
	但是因为产生了网络回路，所以会有一点问题，可能会一直占用
	通过【生成树算法】改进：其实就是生成树，但是会实时变化
【冲突域】同一个局域网（不被隔离的同一端）==网桥可以隔离冲突域==
之前网桥可以沟通不同的网络类型，现在这个工作一般交给路由器了
交换机（现代网桥）：可以提高效率
之前还会用集线器管内部连接，但是现在变便宜了
## VLAN
可能有不一样的要求，所以要隔离
物理拓扑和逻辑拓扑分开
同一种颜色的节点只能转发给同一种颜色的端口
	但是由于hub可能会有点问题，因为不知道是什么颜色的
	-> 增加一个颜色字段！来记一下额外的信息，具有同一个identifier的节点可以互相转发
	因为阻力比较大，所以只有VLAN-aware的设备会增加这个字段，发给不兼容设备的时候就把这个字段删掉
	==颜色需要以端口来划分==
	是不是实现了一种组播的效果：组播还是全部都转发的，只是地址不对的时候扔掉，并非很安全
# WLAN
无线局域网
【背景问题】
1. 不能检测冲突，信号太弱了
2. 传输范围比较有限
【U-NII】【无需许可的国家信息建设band】只要符合要求（比如功率小于10w）就可以不用申请许可，🉑免费用
	e.g. 5GHz频率高，波长短，没那么嘈杂但是传播范围短了
【隐藏终端问题】潜在的竞争者离我太远听不到 所以竞争冲突了  
【暴露终端问题】C监听B，把B给A发当成B给D（目标接收端）发，导致无意义等待
![[Pasted image 20260818141333.png]]
因为发送端只知道发送端是否有其它无线电信号但是不知道接收端是否有其它无线电信号
【MACA】【冲突避免多路访问】A发B前先发RTS（request to sent），B收到之后给A发CTS（clear to sent）听到RTS的站在RTS和CTS之间闭嘴；听到CTS的站在听到CTS和推测结束之间闭嘴
【IEEE802.11】
- 【物理架构】![[Pasted image 20260818142156.png]]
	- 【速率自适应】丢包率大则速率改低，否则速率改高
- 【MAC】：CSMA/CA：听一段时间没人讲话；随机等待一段时间，之后发送所需发送内容
	- 无线信道比较嘈杂 所以必须要发ack；如果没有收到ack则需要重发
	- 区别：从后退开始，冲突比较昂贵
- 【分布式协调】没有中央协调的点
- 【PCF】有中央协调点但是基本不用，因为同一个局域网的节点可能由不同中央电监管
- 【NAV】听到RTS的节点要等到听到ACK之后才能继续发消息，在这中间都不能发消息，叫做NAV；这不能解决暴露终端问题，因为中间不用停的节点要等到听到ACK才能发；没啥用，因为隐藏和暴露终端问题都不多？
【其它解决方法】
- 减小传播速率
- frame变短：传送更小的帧or切片，但是一组fragment组合成一组burst
- saving power：APSD或者Beacon point，一种20ms醒一次一种100ms醒一次
【802.11e】给不同的传输设置不同的优先级，具体表现在DIFS之后的分别等待时间

【TXOP】传输机制把从传输一个单位帧转换成传输一个单位时间，这样就不会拖慢本来传输的比较快的帧
