## 二、项目背景与研究意义

### 项目背景
当前学生在选课时面临课程数量多、组合复杂、个人偏好难以兼顾等问题。现有的选课系统通常仅支持被动筛选，缺乏多目标权衡与自动优化能力，学生需反复手动尝试排课，耗时耗力，效率低下。选课本质上是一个多约束、多偏好的组合优化问题，但目前主要依赖人工试错完成，亟需智能化工具辅助。

### 研究意义
开发一款智能选课助手小程序，旨在：
- 帮助学生快速生成满足个人偏好的课表方案；
- 提升选课效率，减少试错时间；
- 引入多目标优化算法，支持时间、教师、课程难度、学分等多维度权衡；
- 为学生提供直观、可视化的选课决策支持。

## 三、功能需求分析

### 核心功能模块
1. **用户注册与登录**：支持微信授权登录，管理用户基本信息。
2. **偏好建模与输入**：允许用户设定课程偏好（如教师、时间、难度、学分等），并设置权重或优先级。
3. **自动排课与方案生成**：基于用户偏好，通过算法自动生成多个可选课表方案，支持多目标优化。
4. **方案可视化与比较**：以日历或表格形式展示课表，支持多个方案对比与调整。
5. **课程信息查询**：提供课程列表、教师评价、课程时间等信息查询功能。
6. **历史方案管理**：保存用户生成的课表方案，支持查看与复用。
7. **后台管理**：管理员可管理课程数据、用户反馈等。

### 用户角色与权限
| 用户角色   | 功能权限                               |
|------------|----------------------------------------|
| 普通用户   | 登录、偏好设置、自动排课、方案查看与保存 |
| 管理员     | 课程数据管理、用户管理、系统统计       |

# 实现
- 前端重写
- 后段封装
### 大概思路
- **前端**：微信小程序，负责界面和用户操作
- **后端**：Python API 或云函数，负责：
    - 登录教务系统
    - 请求课程数据
    - 返回 JSON 给小程序
```流程图：
小程序前端 <--> 后端 API <--> 教务系统
```
- 小程序只做界面和调用 API，不直接请求教务系统
## 后端
可以复用原 Python 逻辑（requests 部分
1. **提取原 Python 网络请求逻辑**
    - 把 network.py、登录逻辑、课程抓取逻辑封装成 API
    - 可以用 **Flask / FastAPI / Django**
2. **设计 API 接口**
    - POST /login → 登录
    - GET /courses → 返回课程列表 JSON
    - POST /select_course → 提交选课
3. **处理 Cookie / Session**
    - 教务系统可能需要校园网登录
    - 可以在服务器端保存 Session
4. **部署**
    - 云服务器、阿里云 ECS、腾讯云云函数
    - HTTPS 是必须的（小程序接口安全要求）
## 前端
1. **界面设计**
    - WXML + WXSS + JS/TS
    - 页面：
        - 登录页面
        - 课程列表页面
        - 选课操作页面
        - 已选课程展示页面
2. **数据交互**
    - 小程序用 wx.request 调用后端 API
    - 获取 JSON 数据填充页面
3. **状态管理**    
    - 可以用 **小程序的 Page / Component 数据绑定**
    - 也可以用第三方状态管理（如 MobX）
